# Deployment (Cloudflare Pages)

The site is fully static (`astro build` → `dist/`). It needs no adapter, server functions or database, and deploys with
Cloudflare Pages' Git integration: production from `main`, a preview deployment for every other branch and pull
request.

## One-time setup

1. In the Cloudflare dashboard open **Workers & Pages → Create → Pages → Connect to Git** and select the
   `iceman951/elysia-reference` repository.
2. Build settings:

   | Setting | Value |
   | --- | --- |
   | Framework preset | Astro (or None) |
   | Build command | `pnpm build` |
   | Build output directory | `dist` |
   | Root directory | *(empty — repository root)* |
   | Build system version | v3 |

3. Production branch: `main`. Preview deployments: *All non-production branches* (the default), which covers pull
   requests.
4. Environment variables:

   | Variable | Environment | Value | Why |
   | --- | --- | --- | --- |
   | `SITE_URL` | Production | `https://<your production domain>` (e.g. `https://elysia-reference.pages.dev`) | Canonical URLs of local pages, sitemap and `robots.txt`. |
   | `PNPM_VERSION` | Production and Preview | `10.34.6` | Matches `packageManager` in `package.json`; the v3 image otherwise uses its default pnpm 10. |

   Node.js is selected by the `.node-version` file (24.21.0); `NODE_VERSION` is not needed. Preview builds need no
   `SITE_URL`: they use the deployment URL Cloudflare provides (`CF_PAGES_URL`).
5. Optional: add a custom domain under **Custom domains** and set `SITE_URL` to it.

## What happens on each build

`src/config/site.ts` reads the Cloudflare build environment:

| `CF_PAGES_BRANCH` | Environment | Indexing |
| --- | --- | --- |
| `main` | production | allowed (`robots.txt` allows crawling, sitemap published) |
| any other branch | preview | `noindex` on every page and `Disallow: /` in `robots.txt` |

Override with `DEPLOY_ENV=production|preview|development` if needed (for example when the production branch is
renamed, or set `PRODUCTION_BRANCH`).

`public/_headers` sets security headers for all responses, long-lived caching for fingerprinted `/_astro/*` files,
moderate caching for mirrored media under `/upstream/*`, and `noindex` plus a Markdown content type for the `/md/*`
exports.

## Resource limits

The build produces roughly 400 files and 45 MB (most of it mirrored screenshots and two short product videos; the
largest file is about 6 MB), well within the Pages limits of 20,000 files per deployment and 25 MiB per file.
`pnpm build` takes a few seconds; most of a Cloudflare build is dependency installation.

## Deploying without Git integration

```sh
pnpm build
npx wrangler pages deploy dist --project-name elysia-reference
```

(`wrangler` is not a project dependency; it requires `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.) Set
`SITE_URL` in the shell before building for production.

## Verifying a deployment

- `https://<domain>/robots.txt` lists the sitemap on production and disallows everything on previews.
- `https://<domain>/sitemap-index.xml` lists the locally authored pages only (imported pages are canonicalized to
  elysiajs.com).
- On an imported page, `<link rel="canonical">` points to the matching elysiajs.com page.
- Search (`/` or `Ctrl`+`K`) returns results; the index is generated by Pagefind during the build.

## Release safety

Production only changes when `main` changes. Upstream content arrives through reviewed pull requests (see
[SYNC_STRATEGY.md](SYNC_STRATEGY.md)), CI runs the full validation on every pull request and push to `main`, and a
failing build leaves the previous production deployment in place.
